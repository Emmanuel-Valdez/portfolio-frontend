## 01 · Leé antes de empezar

Esta es una consigna para una modalidad asincrónica. Leela completa y avanzá en el orden indicado: cada paso deja una parte visible de tu proceso.

### Qué tenés que hacer, paso a paso

1. Leé toda la consigna antes de crear archivos o pedir ayuda a una IA.
2. Prepará GitHub: tenés que tener un perfil accesible y crear un repositorio público para esta PFO.
3. Creá tu landing de portafolio con HTML y CSS. Debe mostrar tu nombre y apellido, una presentación, tus habilidades, una forma de contacto y una sección personal a elección.
4. Diseñala con libertad: el estilo es libre. Aprovechá la oportunidad para ser creativo/a y tomar decisiones visuales propias.
5. Aplicá los requisitos técnicos: HTML semántico con `header`, `nav`, `main` y `footer`; CSS propio; Google Fonts; Flexbox o Grid; diseño responsive; una transición o animación; imágenes con `alt` y formulario con `label`.
6. Incluí GitHub en la landing: agregá un enlace visible y funcional a tu perfil de GitHub. Luego publicá el proyecto con Vercel.
7. Usá imágenes con criterio: podés usar fotos propias y también procesarlas con IA. Si usás imágenes generadas o intervenidas, registralo en el README.
8. Completá el archivo `README.md` del repositorio: incluí una breve descripción de la PFO1, la URL de Vercel, las decisiones que tomaste y la declaración de uso de IA.
9. Documentá el uso de IA: podés explorar creativamente los límites de la IA generativa que elijas, pero anotá con precisión qué herramienta usaste, para qué, qué plan tenía, qué experiencia previa tenías y qué revisaste o adaptaste con criterio propio.
10. Entregá el enlace del repositorio público en la planilla de entregas, que estará disponible en breve. La entrega es un único enlace: el de tu repositorio.

## 02 · Cómo se evalúa

La rúbrica mira el resultado y también cómo explicás y documentás tus decisiones dentro del repositorio.

### Estructura semántica y HTML

- **No cumple:** faltan etiquetas semánticas obligatorias o el DOCTYPE está mal usado.
- **Cumple:** incorpora secciones y metaetiquetas requeridas.
- **Propone:** estructura impecable y cuatro comentarios explicativos.
- **Supera:** mejora la semántica para accesibilidad con `alt` y roles ARIA pertinentes.

### Maquetación con Flexbox/Grid

- **No cumple:** no utiliza Flexbox/Grid funcionalmente en las tarjetas.
- **Cumple:** organiza las tarjetas o columnas correctamente.
- **Propone:** consigue un diseño responsive fluido con unidades relativas.
- **Supera:** combina ambas tecnologías y justifica técnicamente la decisión.

### Estilización y Google Fonts

- **No cumple:** no vincula Google Fonts o aplica selectores de forma incorrecta.
- **Cumple:** aplica tipografía y personaliza los componentes básicos.
- **Propone:** logra coherencia visual, contraste y jerarquía tipográfica.
- **Supera:** usa variables CSS o variantes tipográficas con intención.

### Interactividad y transiciones

- **No cumple:** no incluye animaciones ni transiciones.
- **Cumple:** implementa al menos una transición o animación funcional.
- **Propone:** incorpora efectos que mejoran la experiencia de forma armónica.
- **Supera:** crea animaciones personalizadas que suman valor técnico y visual.

### Documentación y entrega

- **No cumple:** falta el perfil o repositorio de GitHub, el README o la declaración de uso de IA.
- **Cumple:** entrega un único enlace al repositorio público con README, URL publicada, enlace al perfil de GitHub y declaración de IA completa.
- **Propone:** documenta con claridad y justifica decisiones de diseño y lógica.
- **Supera:** presenta historial de commits organizado y README avanzado.

## 03 · Uso de IA y autoría

**Requisito transversal**

Podés usar IA, pero tenés que explicar cómo la usaste.

- ✓ Completá el `README.md`: nombrá cuál o cuáles herramientas usaste y para qué las usaste.
- ✓ Indicá si usaste un plan gratuito o pago y, si era pago, cuál.
- ✓ Contá brevemente qué experiencia previa tenías con esa herramienta.
- ✓ Explicá qué revisaste, cambiaste o adaptaste con tu propio criterio.

Podés explorar la IA generativa con creatividad. La evaluación valora la comprensión, las decisiones propias y la trazabilidad del proceso, no la ocultación del uso de herramientas.
